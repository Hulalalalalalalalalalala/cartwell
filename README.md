# inkseal

当前版本提供命令行版本查询、单文件 SHA-256 摘要计算，以及文件内容与
已知摘要的核对。

## 构建与运行

```sh
cargo build --offline
./target/debug/inkseal --version
```

输出：

```text
inkseal 0.1.0
```

## 计算文件摘要

```sh
./target/debug/inkseal digest <文件路径>
```

每次调用只处理一个文件。命令读取指定文件的原始字节，以流式方式计算
SHA-256（内存占用不随文件大小增长），并在标准输出写出恰好 64 个小写
十六进制字符，以换行结束，不附带文件名或标签：

```text
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

摘要只取决于文件的原始字节，不包含文件名、路径或时间信息：相同内容
存放在不同位置得到相同结果；空文件得到标准空字节序列的摘要（即上面
所示值）。零字节、非 UTF-8 数据和各种换行形式都原样参与计算，不做
文本解码或换行转换。路径中的空格和非 ASCII 字符按实际路径处理。

命令行参数按操作系统提供的原始字节接收，因此文件名不是合法 UTF-8
的路径同样支持：在允许这类文件名的系统上，它们与普通路径没有区别，
摘要规则完全一致——只对文件原始字节计算，路径中不可解码的字节、
空格和非 ASCII 字符都不参与摘要。命令始终用真实路径访问文件，即使
两个路径只在不可解码的字节上不同，也会分别打开各自对应的文件，不会
因错误信息里显示成相同文字而读错对象。

### 失败与退出状态

- 成功：退出码 `0`，摘要写到标准输出。
- 文件不存在、无法打开、路径指向目录或读取中途失败：退出码 `1`，
  标准输出保持为空，标准错误给出原因并指出出错路径，例如
  `inkseal: cannot open 'nope': No such file or directory (os error 2)`。
  即使已读取部分内容，也不会输出部分内容的摘要。路径无法完整解码为
  Unicode 时，错误信息中的路径以替换字符（U+FFFD）等可见形式呈现，
  仍可辨认且不会导致命令崩溃；该显示文本只用于提示，不会被当作实际
  路径访问。
- 缺少文件路径、多给路径、未知子命令等用法错误：退出码 `2`，
  只在标准错误给出用法提示。

## 核对文件摘要

已经保存过某文件的 SHA-256 摘要时，可以核对当前文件是否仍与它一致：

```sh
./target/debug/inkseal check-digest <文件路径> <预期摘要>
```

每次调用只接收一个文件和一个摘要。命令只读取文件，不改写它，也不创建
任何结果文件。预期摘要必须恰好由 64 个 ASCII 十六进制字符组成，大小写
均可；按它表示的 32 字节摘要值进行比较。命令不会自动去掉空白：带前缀
（如 `sha256:`）、夹有空格、末尾带换行、长度不对或出现非十六进制字符，
都属于用法错误。摘要格式先于文件被校验，因此摘要不合法时不会打开文件，
即使给出的路径也不存在，报告的仍是摘要格式问题。

匹配时退出码为 `0`，标准输出只写 `OK` 和一个换行，标准错误为空：

```text
OK
```

不匹配时退出码为 `1`，标准输出为空，标准错误明确说明内容不匹配，并同时
列出预期摘要和实际摘要，两者都以 64 个小写十六进制字符显示，例如：

```text
inkseal: digest mismatch: content of 'file.bin' does not match the expected digest (expected e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855, actual ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad)
```

核对沿用与 `digest` 完全相同的内容规则：只比较原始字节，不把文件名、
路径和时间算进摘要，不做文本或换行转换，空文件同样可以核对；大文件仍
以流式方式完整读取，内存占用不随文件大小增长。

### 失败与退出状态

- 匹配：退出码 `0`，标准输出为 `OK` 加换行。
- 内容不匹配：退出码 `1`，标准输出为空，标准错误同时给出预期摘要和
  实际摘要（均为 64 个小写十六进制字符）。
- 文件不存在、路径指向目录、无法打开或读取中途失败：退出码 `1`，
  标准输出保持为空，标准错误指出出错路径和具体原因（例如
  `inkseal: cannot open 'nope': No such file or directory (os error 2)`），
  不会把它说成内容不匹配，也不会给出部分内容的摘要。即使已读取部分
  内容，也不会输出部分内容的摘要。路径无法完整解码为 Unicode 时，
  错误信息中的路径以替换字符（U+FFFD）等可见形式呈现，仍可辨认且
  不会导致命令崩溃；该显示文本只用于提示，不会被当作实际路径访问。
- 缺少参数、多给参数、摘要参数不是合法文字，或摘要不是恰好 64 个
  十六进制字符：退出码 `2`，标准输出为空，标准错误说明输入问题并
  给出用法提示。

## Rust 库接口

库提供与命令行同一内容规则的摘要计算：

```rust
use inkseal::digest_reader;

let digest = digest_reader(std::io::empty()).unwrap();
assert_eq!(
    digest.to_hex(),
    "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
);
```

`digest_reader` 接受任何实现 `std::io::Read` 的输入，成功时返回
`Sha256Digest`（可用 `to_hex()` 或 `Display` 得到与命令行一致的十六
进制文本）；读取失败时返回类型化的 `DigestError`，不会把失败当作
成功摘要。密码运算基于 `sha2`（RustCrypto）实现。
